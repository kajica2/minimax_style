Overview
+
⋮
This page is the canonical inventory of every component in the MiniMax design system v3. It pairs with the token files on the design-system workspace — every component below consumes CSS custom properties, never raw values.
💡
Reading guide: this is a working inventory, not a marketing pitch. Use the toggle sections to drill into each component group. The current focus is on the v3 token migration; legacy v2 components are listed in the appendix.
Foundations
▾
Color
11 surface tokens, 4 ink tokens, 2 border tokens, 7 brand accents, 3 semantic.
▾
Typography
Display: Outfit 600. Body: DM Sans 400. Mono: JetBrains Mono. Italics reserved for editorial accents only — emphasis is weight, never slope.

Components
Buttons
+
Three primary variants: primary (ink fill, pill, 14/500), secondary (white, hairline border, pill), and brand (saturated fill reserved for product release identity). All buttons share the same focus ring and disabled state.
+
States: default, hover, active, focus, disabled, loading. Each state has its own token reference.
+
Sizes: small (32px), default (40px), large (48px). Heights are token-driven, not magic numbers.
+
Icon variants: leading icon, trailing icon, icon-only. Icons inherit button text size; never hard-coded to 16px.
Inputs
+
Pill-shaped by default, square inside data-dense forms. Focus ring uses --ink-1 at 8% alpha. Validation states: success (green border), error (red border + helper text), warning (amber border).
Cards
📐
Two card archetypes: documentation cards (16px radius, white, hairline border, 1-step shadow) and product identity cards (32px radius, vibrant gradient, no shadow). Mixing the two reads as inconsistency — pick the archetype per surface.

Code reference
Component implementations live in packages/ui. Every component reads from the token layer — change a token, every component updates.
// packages/ui/src/Button.tsx import { tokens } from "@minimax/tokens"; export const Button = ({ variant = "primary", size = "default", children }) => ( <button className=`btn btn-${variant} btn-${size}`> {children} </button> );
A design system is not a component library. It is a contract: the rules, tokens, and opinions that make your product legible to your team.

Skinning system — warm neutrals, text-first

Notion-style systems are quiet on purpose. The hierarchy is the type, the accent is the link, the warmth is in every surface. To rebrand this document canvas, change the 4 groups below. Every block — callout, code, toggle, todo — reads from the same token set.

Skinning recipe
/* Skin this whole document canvas by changing 4 values. Notion-style systems are quiet — the type does the work. */ :root { --bg: #fbfaf8; /* warm canvas, NOT pure white */ --ink-1: #37352f; /* Notion's signature body ink */ --accent: #2383e2; /* link blue — one chromatic */ --font-sans: "Inter", sans-serif; } /* Result: every H1, every callout, every block hover, every code block, every link inherits the brand. The warmth of the canvas is the brand identity. */
